# MathSpring 題庫擴充操作準則

## 最高優先紅線

先看這裡，再看其他細節。以下任一條不符合，該題不得進 shipping pack：

1. **不得重複**：不可用模板弱變形充數，不可只換數字、故事、單位、圖形尺寸、求量位置（**本文件的第一優先**，細節見「去重規則」與「相似度硬規則」）
2. 不得出現 `MathSpring Editorial Original`
3. 題目要有推理點，能讓學生想一下；不必侷限於奧數題型
4. 上架前必須通過去重閘門與四語系檢查
5. 單一能力題不得偷懶標成 `mixed`
6. 數學表達必須像數學，不可用 `2^2`、`3^15` 這類程式式寫法
7. 幾何圖必須真正畫出題目條件，不能只畫外框再貼標籤
8. 若圖形品質不足或會誤導，寧可不上圖，也不要放錯圖
9. `correctAnswer`、`answer`、`solutionSteps`、`source` 必須彼此一致且完整
10. 每題上架前都要完成複審，通過後才可標 `ok`

## 2026-08-28 政策變更（使用者裁示）

三項調整，其餘規則不變：

| 項目 | 舊 | 新 |
| --- | --- | --- |
| 題目性質 | 必須是真正奧數題 | **取消**。一般數學題、課本延伸題、益智題都可收，只要有推理點 |
| 來源標示 | 每題來源必須明確標示、可個別追溯 | **取消**。`source` 欄位仍要填（schema 與測試依賴它），但不必逐題論證出處與原創性 |
| 不得重複 | 紅線之一 | **維持，且升為第一優先**。這是唯一沒有放寬的限制 |

放寬的理由：題庫要從 2092 題長到每年級 200 題（共 2400 題），
硬守「每題都必須是奧數等級的原創題」會讓通過率低到無法推進——
2026-08-28 那一輪的實測通過率只有 31%（候選 39 題、實收 12 題）。

**論壇題可以參考。** 公開論壇、題庫網站、教材上的好題都可以拿來當題型來源，
照樣要過去重閘門。`source.type` 沿用 `rewritten_olympiad_style` 即可，
`notes` 寫清楚題型出處與改寫程度就好，不必宣稱原創。

## 目的

這份文件是給後續工程師、內容編輯者、或其他模型直接使用的題庫擴充規範。

目標是讓 MathSpring 在持續補題時：

- 題目風格不限，有推理點即可（2026-08-28 放寬）
- 分類與難度一致
- 不重複塞入相似題
- 官方題與改寫題的來源清楚可追蹤
- 能直接對應目前 app 的 JSON schema

本文件日期基準：2026-07-23。

## 內容來源優先順序

題目來源應依照以下順序使用：

1. 官方公開競賽題庫，用來抽取題型、難度、語氣、常見陷阱
2. 官方題的安全改寫版
3. 公開論壇、題庫網站、教材上的題目（2026-08-28 起開放）
4. 依既有題型框架手工設計的新題

補充原則：

- 可以參考任何公開來源的題型結構；收錄的成品要自己重寫成四語系完整題目
- 不可把一題官方題和另一題官方題的條件或數字「混搭」後當成新題
- **不可用同一骨架大量換數字生題**（這條沒有放寬）
- 不可把官方題稍微改句子、改數字、改角色名稱後，就視為安全可收錄成品
- `template` 只能用來分類、校稿與檢查難度，不能直接當成 shipping 題目的生成器

目前建議優先參考的來源（2026-08-28 起不再要求逐題可追溯）：

- Math Kangaroo USA 歷年 PDF 與解答
- IMC Taiwan 官方試題
- AMC / AIME 官方或公開可追溯題源
- 華文圈公開國中高中數學競賽題庫
- 其他具官方身分、公開可查證的國小數學競賽卷
- 公開的數學論壇、題庫網站、學校教材與講義

補充：

- `grade7` 到 `grade12` 第一批內容可同時混用華文圈與國際公開競賽來源
- ~~但每題仍必須個別可追溯，不可只寫大類來源~~（2026-08-28 取消）

## 版權與可收錄邊界

除非已確認可重製權利，否則不要預設官方題可以直接原文打包進 app。

規則如下：

- 只把官方題當成題型與難度基準：可直接研究
- 要放進 app 的內容：優先使用改寫題
- 若已明確決定收錄官方題：每題必須補完整 `source`
- 若權利狀態不明：保留 `source.type = official_reference`，但不要假設可以大規模照抄

對 `grade7` 到 `grade12` 第一批尤其重要：

- 可收錄的是「改寫後版本 + 完整來源追溯」
- 不是「直接把原文 contest 題複製進 JSON」

## 題目準則

每題都必須符合以下最低標準：

- 有推理點，不是單步直算（2026-08-28 放寬：不再要求奧數型）
- 有唯一明確答案
- 題目本身必須具有獨特性，不能只是既有題的弱變形
- 題幹敘述直白，不使用模糊代稱或不必要包裝語
- 有完整解題步驟，不只給答案
- 能明確歸入既有 `topic` 與 `subtopic`
- 能判定難度
- 若需要圖形，圖形可由 app 內直接繪製或以穩定方式呈現

不應收錄的題：

- 只有直接套公式、無推理的純計算題
- 條件不完整或可能多解
- 和既有題只有換數字、沒有新推理差異
- 用詞不自然，像是機器直接生成的題
- 超出該年級認知範圍太多
- 雖然可解，但和正式競賽題相比明顯更像一般學校數學題

## 獨特性硬規則

本專案要求的「新題」必須是**完整成品層級的全新題目**，不是既有題的表面改寫版。

以下情況一律**不算新題**：

- 只改數字，其他條件與解法骨架不變
- 只改角色、物件、故事場景，數學結構不變
- 只把同一題移到別的年級、別的 pack、或別的主題名稱下
- 只把選項順序、問法語氣、已知與未知的位置互換
- 只加一個不影響解法的小限制，但核心推理完全相同
- 看似結合兩題外觀元素，實際仍是同一條解法流程

MathSpring 對「不可重複」的要求，指的是：

- **必須是完全不同的題目**
- 而不是「外表不同、實際只是換皮」

判定時，請忽略數字、名稱、單位與故事包裝後，再問：

- 這題和既有題是否仍是同一個解法流程？
- 是否仍在考同一個陷阱、同一個轉折、同一種觀察？
- 是否只要把舊題的數字代掉，就能直接得到這題？

只要答案偏向「是」，就視為重複，不得入庫。

## 難度規則（phase 1：不分難度層）

phase 1 **只有一個維度來表示難易：年級（`levelStage`，grade1–grade6）**。不設獨立的難度分層。

- `difficulty` 與 `challengeTier` 兩個欄位**固定填 `foundation`**，作為 schema 佔位，不用來區分難易，也不得填 `advanced` 或 `competition`。
- 廢除舊文件的難度分層制（不論兩層或三層）。不要再新增 advanced / competition 題，也不要用這兩個值。
- 難度由「年級」決定：同一年級內的題目視為同一池，不再細分基礎/進階/競賽。

判定原則（以年級為準）：

- 題目難度須貼齊該 `levelStage`（見「年級與競賽級別規則」）。
- 過難或過易都算不符：明顯超出該年級認知的題不要收；低於該年級兩級以上的裸題也不要收。
- 難度提升不能只是數字變大；但也不要為了「更難」而超出年級範圍。

## 類別與子分類規則

主分類使用既有 `topicCode`：

- `arithmetic`
- `geometry`
- `logic`
- `mixed`

新增題目前，先判斷它是否能落入已存在的 `subtopic` family。

若能落入既有 family：

- 優先沿用

若不能：

- 先確認是否真的需要新 `subtopic`
- 不要隨意發明只用一次的臨時子分類

補充硬規則：

- 若題目的核心能力明確屬於單一領域，不得偷懶標成 `mixed`
- `mixed` 只保留給真正跨兩種以上能力、且無法合理收斂到單一既有 `topic + subtopic` 的題
- 例如餘數、同餘、奇偶、倍數判定這類題，不得只因為「不想細分」就標成 `mixed`
- 若 UI 顯示出來只剩「綜合」而無法幫助使用者理解題型，代表分類過粗，該題不得上架

## 去重規則

新增題目前，必須先檢查是否已有「同型題」。

### 2026-09-03 政策變更（第三次放寬）：同一概念換個敘述可以收

使用者裁示：**「同樣概念、換個敘述來表示，也是可以的。」**

這一條放寬的是先前「只換故事／換角色／換敘述視為重複」那條紅線。
現在的界線改成：

| 情況 | 判定 |
| --- | --- |
| 連數字、問法、解法都相同（實質同一題） | **仍然淘汰** |
| 同一概念，但情境、數值與計算過程不同 | **可以收** |
| 同一概念，換個敘述方式呈現（例如求和改成求項、正推改成逆推） | **可以收** |
| 同一模板只把數字放大、或平移到別的年級而無新意 | **仍然淘汰** |

換句話說，**判斷重心從「像不像」移到「解起來是不是同一件事」**。
2026-09-03 依這條重新收了先前被擋下的「劇場座位求總和」（既有題求第 n 項）
與「直角三角形內切圓半徑」（既有題用海龍公式）。
仍然維持淘汰的是「8×8 缺角棋盤鋪骨牌」——它和 `logic_grade12_033`
連數字、問法都一模一樣，屬於實質同一題。

### 用標籤提高比對精準度（2026-09-03）

全庫 2528 題已打上 `c:` 概念與 `m:` 手法標籤，比對時應該同時看兩個軸：

```bash
python3 scripts/question_similarity_audit.py --tags [門檻]   # 預設 0.35
```

- **共同 `c:` 為 0（disjoint）** → 數學上無關，**直接放行，不必人工讀**。
  2026-09-03 有 3 筆誤判就屬於這類（例如三集合排容 vs 個位是 3 的質數，
  相似度 0.42 但共同概念為零）。
- **`c:` 完全相同（identical）** → 即使字面相似度低也要人工複判。
  這是純文字閘門的盲點——`geometry_grade6_033` 就是這樣漏掉的。
- **部分重疊（overlap）** → 照字面相似度的一般規則處理。

出題時也可以反過來用：先查目標概念已經有哪些題，直接看解法骨架，
比事後靠相似度分數篩選精準得多。

### 2026-09-03 政策變更（第二次放寬）：相似度分數只是提示，不是判決

使用者裁示放寬審題標準（與先前放寬「奧數題型」「來源必須是競賽卷」同一性質）。
**放寬的是「字面相似度」的自動淘汰，沒有放寬「不得重複」本身。**

`question_similarity_audit.py` 用的是字元 3-gram，會把**共用問句模板**的題判成相似，
即使兩題數學上毫無關係。實例（2026-09-03）：

| 候選 | 被判撞的既有題 | 分數 | 實情 |
| --- | --- | --- | --- |
| 1 到 1000 中不被 2、3、5 整除的數有幾個 | 1 到 100 中個位是 3 的質數有幾個 | 0.42 | 只共用「在 1 到 N 之中…有幾個」，數學無關 |
| 長 300 寬 240 求最大正方磚的塊數 | 6×4 房間用 2×2 地磚幾塊 | 0.42 | 前者要先求最大公因數，後者直接除 |
| 等高三角形面積比＝底邊比 | 塞瓦線 AD 與 BE 交點的比例 | 0.50 | 難度與推理核心都不同 |
| 2019 枚硬幣任翻 2 枚問可不可能 | 8 枚硬幣翻相鄰 2 枚求最少次數 | 0.44 | 一個是奇偶不變量的不可能性，一個是計數 |

**新的判定方式：**

- **分數 < 0.40**：放行。
- **0.40 ≤ 分數 < 0.55**：進人工複判，**只有「解法骨架相同」才淘汰**；
  若兩題的推理核心、陷阱結構或所求量型態不同（例如整數答案 vs 可不可能），可以收。
- **分數 ≥ 0.55**：預設淘汰。要收必須在 `source.notes` 明確寫出不同的推理核心。

**放寬之後，人工複判必須看「全部配對」而不是「最高分那一筆」。**
`--candidates` 模式每個候選**只回報分數最高的一筆**，真正的重複可能被分數更高的
誤判蓋住。2026-09-03 就發生過：候選「BD:DC = 2:3、三角形 ABD 面積 24，求 ABC 面積」
最高分配對是 `geometry_grade11_013`（塞瓦線交點比，0.50，確為誤判），
但庫裡的 `geometry_grade6_033` 是**連數字都相同的同一題**，只因措辭不同而落在 0.46，
在候選階段完全看不到。該題寫入後靠全庫重掃才發現並撤除。

所以正確流程是：候選階段用 `--candidates` 粗篩 → 寫入後用該批 id 清單跑
**全庫重掃**（`question_similarity_audit.py 0.40 ids.txt`）→ **逐筆讀完 0.40 以上的
每一個配對**，不能只看最高分。這一步在放寬之後比放寬之前更重要。

**下列情況不因本次放寬而改變，一律仍視為重複**（見上方清單）：
只換數字、只換底數、只換故事或角色、只換求量位置、同骨架平移到別的年級。
2026-09-03 有 8 題候選就是因為這幾條被淘汰，其中「8×8 缺角棋盤鋪骨牌」
與 `logic_grade12_033` 連數字都相同，屬於必須擋下的真重複。

視為重複或高度重疊的情況：

- 題幹只換數字，推理骨架完全相同
- 圖形只換尺寸，核心結論相同
- 選項不同，但解法與陷阱結構相同
- 只是把同一模板 family 平移到另一年級，沒有新增新的推理轉折
- 平均數、比例、餘數、逆推等題型若僅更換數值規模，也視為重複
- 把既有題改寫成另一個故事版本，但解法步驟仍一一對應
- 只把「求哪個量」互換，例如原本求總數、現在改求其中一部分，但推理完全同骨架
- 同一圖形只換尺寸、標記字母或角度數值，結論與思路不變

視為可共存的情況：

- 同一模板 family，但難度層不同
- 同一主題，但解題核心不同
- 同一題型，卻引入新的結構條件或錯誤誘因
- 同一能力目標，但推理路徑明顯不同

實務流程：

1. 先找相同 `topic + subtopic`
2. 再比對解法骨架
3. 再比對是否只是同一能力模板的弱變形
4. 若只是數字換皮，不新增
5. 若是同型進階版，必須能明確指出新增的推理轉折後才可新增

### 去重判定問題（必答）

每題上架前，至少要回答以下問題：

1. 若把所有數字改掉，這題是否仍和既有某題是同一題？
2. 若把情境敘述拿掉，只留下數學條件，是否仍能和既有某題一一對應？
3. 這題新增的差異，是否真的改變了解題策略，而不只是改變計算量？
4. 若把這題交給熟悉題庫的人，他是否會立刻說「這就是某題換數字版」？

只要其中一題答案偏向「是」，就不得視為新題。

## 新題處理流程

每次補題請照這個順序：

1. 從官方題庫整理候選題
2. 為每題標記：
   - 來源
   - 對應年級或競賽級別
   - topic
   - subtopic
   - difficulty
3. 對照現有題庫做去重
4. 決定：
   - 直接收官方題
   - 改寫成 app 版
   - 不收
5. 確認成品是否為原創且不屬於模板弱變形
6. 做一次「題目複審」（不是模板弱變形 + 至少有一個推理點）
7. 複審不合格就淘汰或重寫，不得因為可解或欄位完整而放行
8. 補齊 JSON 欄位
9. 若有圖，確認 renderer 支援
10. 更新 `manifest.json`
11. 跑題庫解析與 widget 測試

## 題目複審規則（2026-08-28 放寬）

每一題在完成初稿後，必須再做一次獨立複審。
原本這一節要求「必須保有競賽感、不得是一般數學題」，該項已取消。

**現在只有兩項是硬性的：**

1. **不是模板弱變形**——不可只換數字、名詞、單位或情境包裝。
   要能清楚說出：這題和題庫中最接近的既有題相比，新增了哪一個真正不同的推理點。
2. **至少有一個推理點**——不是單步直算就能得到答案。
   純粹的裸和差、裸平均、裸連加、裸逆運算、裸代公式仍然不收，
   因為那既沒有推理點，也和題庫裡大量既有題撞在一起。

**已取消的檢查：**

- ~~和公開正式競賽題相比是否仍保有競賽感~~
- ~~是否符合對應競賽級別的思考深度~~

換句話說：一題只要「有東西可想」而且「不和既有題重複」，就可以收。
不必再問它像不像競賽題。

未通過第 1 或第 2 項者：

- 不得標記為完成
- 不得寫入 shipping pack
- 必須重寫或淘汰

## 模板使用邊界

`olympiad-template-spec.md` 與 `olympiad-template-registry.md` 的用途是：

- 幫題目分類到正確 family
- 幫內容編輯者校對難度與能力目標
- 幫審稿時確認題目仍有推理結構

它們**不是**：

- 題目量產器
- 只換數字的出題腳本依據
- 可直接對不同年級複製貼上的生題模版

若一題能被描述成「只是某模板的另一組數字」，那題通常不應上架。

每題至少要有：

- `id`
- `topic`
- `subtopic`
- `difficulty`
- `levelStage`
- `challengeTier`
- `prompt`
- `answer`
- `solutionSteps`
- `figure`
- `answerMode`
- `correctAnswer`
- `source`

- `options`
- `inputConstraints`

## 主題與選項的年級差異（2026-08-28 依實際題庫與 app 行為校正）

先前本文件的「四類 topic」與「固定 4 個選項」是照 grade1-6 寫的，套到 grade7-12 會誤判。實際規則如下：

- **pack 層 `topicCode`**：grade1-6 用 `arithmetic` / `geometry` / `logic` / `mixed` 四類；grade7-12 用
  `algebra` / `combinatorics` / `geometry` / `logic` / `number_theory` 五類（每年級 5 個 pack）。
  app 端 `displayTopicCode`（`lib/main.dart`）對這七個代碼都有多語系標籤。
- **mixed pack 的每題 `topic`**：刻意記錄該題實際所屬領域（可以是上述任一個），pack 層 `topicCode` 才是 `mixed`。
  不要把 mixed pack 裡的每題 topic 一律改成 `mixed`，那會丟失分類資訊。
- **選擇題選項數**：允許 3 至 5 個，鍵必須是連續的 A、B、C…
  - 3 個：題幹本身只給三個候選（例如「甲乙丙誰是第一名」），硬湊第 4 個選項反而更差。
  - 4 個：grade1-6 的預設。
  - 5 個：grade7-12 對齊 AMC 體系的題目，AMC 10/12 本來就是五選項。
- **`kangaroo56` pack 的 id** 以競賽而非年級命名（`mixed_kangaroo56_foundation_NNN`），是既有慣例，不要改。

## 相似度硬規則（2026-08-28 使用者裁示）

**新題不只推理核心要不同，題幹情境也不可以像。** 判準是：把兩題並排讀，如果會覺得「這兩題長得一樣、只是問法不同」，就不算新題。理由是題目多而互相接近，等於沒有增加練習價值。

- 已存在的例外：grade7-12 有 13 組「情境相同、問法不同」的題（例如河內塔加上只能搬相鄰柱、鴿籠改成指定顏色）。
  這批經審視後保留——它們的遞迴式與最壞情況構造確實不同，學生無法套用前一題的方法——但**不得再新增同類**。
- 實際後果：grade7-12 已飽和（900 題／896 個 subtopic），不使用「同 subtopic 換問法」就幾乎補不了題，
  因此後續擴充應集中在 grade1-6。
- **數量讓步給品質**：某個年級如果找不到足夠多真正不同的題型，就少補幾題，不要湊數。

### 相似度指標：一定要看重疊係數，不能只看 Jaccard

Jaccard 對「同一題但一邊寫得比較囉嗦」很脆弱——聯集被長的那一邊撐大，分數被稀釋。
實例（2026-08-28 事後才發現）：

| 配對 | Jaccard | 重疊係數 |
|---|---|---|
| `arithmetic_grade4_073` vs `arithmetic_grade6_009`（頁碼共用幾個數字，同題換數字） | 0.27 | **0.62** |
| `geometry_grade3_056` vs `geometry_grade7_016`（三角形內角比求最大角） | 0.31 | **0.56** |

這批題就是這樣通過 0.40 的 Jaccard 閘門而入庫的，事後重掃才移除。
`scripts/question_similarity_audit.py` 現在取兩者的最大值，短題幹（< 25 個 3-gram）
只用 Jaccard，避免重疊係數在短句上虛高。

### 同答案值檢查（2026-08-28 新增，改寫政策的必要配套）

改寫情境會**降低字面相似度**。如果兩題本來就是同一題，改寫等於把重複藏起來，
而不是消除它。實例：`number_theory_grade9_032` 被改寫成旅館房號後，
相似度工具再也抓不到它和 `number_theory_grade7_002` 是同一題（答案同為 243）。

因此每次改寫或補題後，除了字面相似度，還要跑：

```
python3 scripts/question_similarity_audit.py --same-answer 0.55
```

它比對「答案值相同 + subtopic 名稱重疊過半 + 字面仍有相似」的配對。
單看答案值會有大量雜訊（很多題答案都是 A 或 4），三個條件同時成立才報。

### 工具攔不到的，一定要人工複查

閘門靠字面，抓不到「換情境同骨架」。2026-08-28 那一輪 grade5/grade6 共淘汰 21 題，
其中 18 題是人工比對最接近的既有題才發現的。判準只有一條：
**拿掉數字與故事之後，這題和既有題是不是一一對應？**

### 出題前必跑（不是出題後）

`scripts/question_similarity_audit.py` 把題幹去掉數字、單位與人名後取字元 3-gram 算 Jaccard 相似度。
數值驗證與 schema 檢查都抓不到撞題，這是必要的第二道關卡。

```bash
python3 scripts/question_similarity_audit.py 0.45              # 全庫兩兩比對
python3 scripts/question_similarity_audit.py 0.45 ids.txt      # 只看清單內的題
```

**在寫入題庫之前**就先把候選題幹拿去比對；相似度 0.5 以上一律重新設計。經驗上，最常撞的不是與既有題撞，
而是**同一批新題彼此互撞**——本輪就有三組是這樣被抓出來的（整數邊三角形計數、格子數圖形、位值擺數字求最大乘積）。

## 自動檢查

`scripts/validate_question_packs.py` 把本文件可程式化的部分寫成檢查（schema、四語系、答案一致性、
`geometry_scene` 的座標自洽、manifest 一致性）。用法：

```bash
python3 scripts/validate_question_packs.py            # 全部
python3 scripts/validate_question_packs.py grade3     # 單一年級
```

圖的目視檢查用 `scripts/dump_figure_previews.py`，它會從真實題包挑題、渲染成 PNG：

```bash
python3 scripts/dump_figure_previews.py --kind composite_grid_shape
python3 scripts/dump_figure_previews.py --id geometry_grade9_foundation_009
python3 scripts/dump_figure_previews.py --grade grade9 --out /tmp/figs
```

輸出資料夾裡除了 PNG 還有 `index.txt`（題號對題幹），看圖時才知道每張圖在問什麼。
底層是 `test/figure_preview_test.dart`，走 app 自己的 `buildFigureRenderSpec`，
所以**五種 kind 都畫得出來**，畫面也跟 app 裡一致；也可以自己準備資料夾放
`figspec.json`（`[{"id": ..., "kind": ..., "params": ...}]`）再帶 `FIG_DIR` 直接跑，
沒帶 `FIG_DIR` 會自動跳過。

**驗證器過不代表圖是對的。**它只看得出 params 的形狀合不合法，看不出圖有沒有
畫錯題意——2026-09-04 就是靠目視才發現「圓內接正方形」那題只畫了一個空圓、
「兩種拼法周長相差」那題只畫了其中一種拼法。新增附圖的題請至少看過一次。

## answerMode 規則（phase 1 硬規則）

phase 1 **只允許**兩種 `answerMode`，不得新增其他型別：

- `multiple_choice`
- `integer_input`

明確禁止（後續模型不得自行擴充）：

- 分數輸入（fraction input）
- 小數輸入（decimal input）
- 自由文字輸入（free-response text）

若一題的自然答案是分數或小數，必須改寫成整數作答（例如問「幾毫升」而非「幾公升」），或改成選擇題；不可為它發明新的 answerMode。

> 目前的品質閘門清單與剩餘待辦見 [question-bank-handoff.md](question-bank-handoff.md)。

## schema 欄位必填/可省規則

- `figure`：**每題都必須有** `figure` 欄位。無圖題填 `{"type":"custom","kind":"none","params":{}}`；有圖題 `kind` 必須是 renderer 實際支援的值，且 `params` 需符合該 kind 的 schema。renderer 畫不出的圖（角度器、一筆畫的動態過程等）一律 `kind:none`，不可硬塞畫不出的參數。

  renderer 實際支援的 kind 與各自的取捨（switch 在 `lib/main.dart` 的 `_buildFigureRenderSpec`）：

  | kind | 用途 | 驗證器檢查 |
  |---|---|---|
  | `geometry_scene` | **需要畫出構造的幾何題一律用這個**：點、線段、多邊形、圓弧、角度標記、直角記號、等長刻記。座標是數學座標（y 軸向上）。 | `scene_checks()` 查 7 項：點在 bounds 內、弧不出界、引用的點存在、直角真的是 90°±0.5°、等長真的等長（1% 容差）、角度標籤與實際角度相符、多邊形頂點不共線 |
  | `coordinate_plane` | 座標平面上的點、折線、標記點。`points` 畫藍點＋標籤，`path` 畫一條青色折線，`highlightPoint` 不會自己畫點、只把 `points` 裡座標相同的那一點改成紅色。**畫不出箭頭，所以不要用它畫向量**——把終點標成「u」會讓學生以為 u 是一個點，而兩個向量只能連成一條折線，看起來是一條折線而不是兩個向量。 | 只查「終點」標籤洩漏答案這一條 |
  | `shape_diagram` | 單一基本形狀＋最多 5 個文字標籤（`top`/`bottom`/`left`/`right`/`center`） | 無 |
  | `composite_grid_shape` | 方格拼出的複合圖形，`filledCells` 是 0-indexed 的 `[row, col]`，row 0 在最上面 | 無 |
  | `circle_quadrants_point` | 只畫得出一種構圖：圓、圓周四等分點（標籤寫死 A/B/C/D）、一個內部點 P，四條連線把圓分成四塊。位置全部寫死不能設定，能調的只有 `shadedRegion`（四個象限名）、`regionLabels`（同樣四個鍵）與 `pointLabel`。構圖不吻合就別用。 | 無 |

  **未列在 switch 裡的 kind 會靜默不畫**——回傳 null、畫面一片空白，
  只在 debug console 留一行 log。五種 kind 的 `params` 現在都有驗證器檢查
  （形狀、範圍、鍵名），但**驗證器過不代表圖是對的**：它看不出圖有沒有畫錯題意。
  新增附圖的題一定要用 `scripts/dump_figure_previews.py` 目視確認（見「自動檢查」）。
- `options`：**只有** `multiple_choice` 有；固定 4 個選項 A/B/C/D，四語系齊全，選項互不重複，`correctAnswer.value` 必須指向其中一個 key。`integer_input` 題不得出現 `options`。
- `inputConstraints`：**只有** `integer_input` 有，必填 `allowNegative`（bool）與 `maxDigits`（int）。`multiple_choice` 題不得出現 `inputConstraints`。
- `correctAnswer`：`multiple_choice` 用 `{"type":"choice","value":"<A-D>"}`；`integer_input` 用 `{"type":"integer","value":"<字串數字>"}`。其值必須與 `answer` 文字、`solutionSteps` 結論三者一致。
- `source`：每題必填；shipping pack 可使用 `official_reference` 或 `rewritten_olympiad_style`。但無論官方題或同水準原創題，都必須通過相同複審。
- `solutionSteps`：四語系陣列長度必須一致（每個語言步數相同）。

## source 填寫規則

目前 shipping 題庫允許官方題與通過複審的同水準原創題並行收錄。

- 不得在上架 pack 中出現 `MathSpring Editorial Original`
- 不得用自製 editorial source 暫代正式出處
- 若不是官方題，必須明確標為 `rewritten_olympiad_style`，並補可追溯的參考來源或設計依據
- 來源欄位不只是顯示用途，也用來做正式性與版權風險審核

### 改寫題

使用：

- `source.type = rewritten_olympiad_style`

限制：

- 可進入正式 shipping pack，但前提是：
  - 題目品質達到與官方題同水準
  - 已通過題目複審、去重檢查、圖形與排版檢查
  - `source` 中已清楚交代參考來源或設計依據

並填：

- `name`
- `reference`
- `notes`

### 官方題

使用：

- `source.type = official_reference`

並盡量填：

- `contest`
- `year`
- `division`
- `problemNumber`
- `displayText`
- `sourceUrl`

`displayText` 不需要多語系，保留原語言即可。

## 圖形題規則

> 需要畫出構造（中點、中線、角平分線、交點、陰影區、圓弧）的幾何題，一律用宣告式規格 `geometry_scene`，由 AI 補精確座標、renderer 畫向量圖。完整規格見 [geometry-figure-spec.md](geometry-figure-spec.md)。舊的「基本形狀＋文字標籤」不得再用於需要構造的題。

若題目需要圖形，優先順序如下：

1. 現有 `CustomPainter` 可直接支援
2. 在現有 renderer 上新增可重用 figure kind
3. 最後才考慮靜態素材

原則：

- 幾何題盡量不用點陣圖
- 圖形必須能跟著 app 穩定縮放
- 同一種圖形 family 儘量抽象成 reusable `figure.kind`
- 圖形必須真正表達題目條件，不能只畫一個大概的框再貼文字標籤
- 若題目要求「連起來形成三角形／切割區域／陰影部分／中點／交點／垂直／平行」，圖上就必須真的畫出那些點、線、區域與關係
- 點位標記必須落在正確幾何位置；不可把頂點字母漂在邊中央附近，造成誤解
- 標籤不可遮擋圖形主體，也不可取代幾何元素本身
- 標籤不可彼此重疊，也不可壓在線段、頂點圓點、角弧、虛線或陰影邊界上
- 若 renderer 目前畫不出足夠精確、會造成歧義，該題不得先用劣質示意圖硬上；要嘛補 renderer，要嘛先不收
- 若圖對理解沒有實質幫助，寧可 `kind:none`，不要放一張品質差且誤導的圖

### 幾何圖複審問題（必答）

每張幾何題圖上架前，至少回答：

1. 只看圖，不看詳解，能否明確辨識題目要用的點、線、區域？
2. 圖上是否真的畫出了題目聲稱存在的幾何關係，而不是只用文字代替？
3. 目前圖是否可能讓人誤認頂點、中點、交點或陰影區域的位置？
4. 若拿掉題幹，只靠圖本身，它是否仍是有用的解題資訊，而不是裝飾？

若任一題答案偏向否，該圖不合格。

## 數學排版規則

- 題幹與選項中的數學表達必須優先使用標準數學寫法，不可用程式語法湊合
- 例如冪次應顯示成 `3¹⁵` 或等價的數學排版，不要直接寫 `3^15`
- 比、分數、根號、角度、座標、集合記號也應維持數學閱讀習慣，避免看起來像程式字串
- 若目前 renderer / text pipeline 不支援較佳寫法，至少要選擇對一般學生直觀的 Unicode 數學字元，不得退回工程師式記號

## 多語系規則

目前題目內容至少維持：

- `zh-Hant`
- `zh-Hans`
- `en`
- `ja`

規則：

- 以繁中作為主編輯版本
- 再補簡中、英文、日文
- 若官方來源本身為中文或英文，`source.displayText` 保留原文即可
- 題幹翻譯需保留數學條件精確性，不可只做語感翻譯

## 年級與競賽級別規則

雖然 UI 現在以競賽級別為主，但題庫仍保留 `levelStage`。

擴題時請遵守：

- `grade1` 到 `grade2`：袋鼠 1-2 的體感
- `grade3` 到 `grade4`：袋鼠 3-4 的體感
- `grade5` 到 `grade6`：袋鼠 5-6 與國小競賽複賽體感

`grade7` 到 `grade12` 的對應競賽級別如下（2026-08-13 確立）：

| `levelStage` | 對齊競賽 | 判準說明 |
| --- | --- | --- |
| `grade7` | IMC Taiwan 複賽 7 年級 / AMC 8 | 國中前段，基本代數與計數技巧 |
| `grade8` | IMC Taiwan 複賽 8 年級 / AMC 8 | 含二次式、等比數列、基本組合 |
| `grade9` | IMC Taiwan 複賽 9 年級 / AMC 10A | 二次函數、相似、基本數論 |
| `grade10` | AMC 10 | 高中前段，代數／幾何／數論基本技巧的組合運用 |
| `grade11` | AMC 12 | 含三角、對數、複數、進階函數 |
| `grade12` | AIME 入門層 | 需多步推理，答案為 0-999 整數的題型體感 |

判定原則：

- 明顯低於基準兩級的裸題不收
- 明顯超出基準的（例如 `grade10` 出現 IMO 層級）改放高年級或不收
- 不得用難度層容納超綱題；`difficulty` 與 `challengeTier` 仍固定 `foundation`

若題目明顯過難：

- 不要硬塞進該年級 pack
- 改放到更高年級的 pack，或直接不收；不要用難度層來容納超綱題

## 上架驗收 checklist（每次補題後逐項核對）

每一題、每一次補題後，必須逐項打勾；任一項不過即不得寫入 shipping pack。

結構與 schema：

- [ ] JSON 可正常 parse
- [ ] `id` 唯一、且符合 `<topicCode>_<levelStage>_<challengeTier>_<serial>` 命名（`challengeTier` 固定為 `foundation`）
- [ ] `topic`/`topicCode` 屬四類之一（arithmetic/geometry/logic/mixed）
- [ ] `difficulty` 與 `challengeTier` 皆固定為 `foundation`（不分難度層；不得用 advanced/competition）
- [ ] `subtopic` 屬 registry 允許集合（見 `question-bank-subtopic-registry.md`）
- [ ] `answerMode` 為 `multiple_choice` 或 `integer_input`（無其他型別）

四語系：

- [ ] `prompt` / `answer` / `solutionSteps`（＋ `options` 若有）四語系齊全（zh-Hant/zh-Hans/en/ja）
- [ ] `solutionSteps` 四語系陣列長度一致
- [ ] 翻譯保留數學條件精確性，非僅語感翻譯

答案一致性：

- [ ] `correctAnswer` 與 `answer` 文字、`solutionSteps` 結論三者一致
- [ ] 已獨立重算/窮舉驗證答案正確（不只信任初稿）
- [ ] `multiple_choice`：恰好一個正解、四選項不重複、`correctAnswer.value` 指向存在的 key
- [ ] `integer_input`：`inputConstraints` 有 `allowNegative` 與 `maxDigits`，且無 `options`

figure：

- [ ] 無圖題填 `kind:none`；有圖題 `kind` 為 renderer 支援值且 `params` 合法（座標在畫布範圍內、shape 為支援形狀）
- [ ] 圖與題意相符（圖是解題必要資訊，非裝飾），renderer 能穩定 render
- [ ] 幾何關係有真的畫出來，不是只靠文字標籤暗示
- [ ] 點位、邊、陰影區、連線位置不歧義；不會把頂點誤畫成中點、把標籤誤當幾何元素
- [ ] 標籤彼此不重疊，且不會壓到頂點、線段、圓點、角弧、虛線或陰影邊界

題面與排版：

- [ ] 題目主題不過粗；能明確落到正確 `topic + subtopic`，非偷懶標 `mixed`
- [ ] 題幹中的數學記號不是程式語法（例如 `^` 冪次記法），而是一般學生可直接閱讀的數學排版
- [ ] 題目顯示層級與學制一致：國高中題不得以「小七、小十、小十二」這類不成立標示出現

source：

- [ ] 每題 `source` 存在且完整；shipping pack 可為 `official_reference` 或通過複審的 `rewritten_olympiad_style`
- [ ] 未把官方題原文照抄進 app（除非 rightsStatus 已 cleared）
- [ ] 未出現 `MathSpring Editorial Original` 或其他自製來源暫代正式出處

去重與題目品質：

- [ ] 已對同 `topic + subtopic` 做去重比對，非既有題的換數字弱變形
- [ ] 已確認這題和最接近的既有題相比，屬於**完全不同題目**，不是換數字、換故事、換求量位置的改寫版
- [ ] 已通過「題目複審規則」的兩項硬性檢查（非模板弱變形、至少有一個推理點）

pack 與測試：

- [ ] `manifest.questionCount` 與實際題數一致
- [ ] 通過題庫解析與 widget 測試

## 去重要跑兩道閘門，不是一道（2026-08-29 新增）

grade12 這一輪，兩題重複是 `tool/question_bank_duplicate_audit.dart` 抓到的，
字面相似度閘門完全放行：

| 新題 | 撞到 | 字面相似度 | dart 稽核 |
| --- | --- | --- | --- |
| `geometry_grade12_033` 正六邊形邊長 4 求最長對角線 | `geometry_grade10_022` 邊長 6 求最長對角線 | < 0.42（放行） | 抓到 |
| `combinatorics_grade12_040` 四種水果買 6 個 | `combinatorics_grade9_035` 四種口味買 3 杯 | < 0.42（放行） | 抓到 |

兩者抓的東西不同，缺一不可：

- `scripts/question_similarity_audit.py`：比**字面**（3-gram Jaccard 與重疊係數）。
  換了故事和用詞就會漏，但能跨子分類抓到「不同名字、同一題」。
- `tool/question_bank_duplicate_audit.dart`：比**同 topic + 同 subtopic + 結構標籤**。
  對「只換數字」極敏感，但前提是子分類名要照概念老實取——取一個新名字就繞過去了。

所以子分類命名要誠實，不要為了避開稽核而發明新名稱，那等於自己關掉安全網。

### 寫入用的最終文字必須再過一次閘門

同一輪還有三題是這樣漏掉的：候選階段的措辭通過 0.42 門檻，我在寫進 JSON 時
把題幹改得更順、也更接近既有題，分數從 0.4 以下升到 0.5–0.7。實例：
`geometry_grade12_033` 候選寫「拋物線 y² = 4x 的焦點到它的準線的距離是多少？」
（放行），寫入時改成「拋物線的方程式是 y² = 4x。它的焦點到準線的距離是多少？」，
與 `geometry_grade11_019`「拋物線的方程式是 y² = 12x。求它的焦點到準線的距離。」
相似度 0.72。

**閘門過的是候選文字，不是成品文字。** 寫入後一定要用該年級的 id 清單重掃一次：

```
python3 scripts/question_similarity_audit.py 0.42 <該年級 id 清單>
python3 scripts/question_similarity_audit.py --same-answer 0.5
dart run tool/question_bank_duplicate_audit.dart
```

## 第三道閘門：模板掃描（2026-08-29 新增）

前兩道閘門都有各自抓不到的東西。2026-08-29 用新做的
`scripts/question_template_scan.py` 掃全庫，一次找出 5 個模板家族與 30 組
兩題配對、共替換 48 題——**其中沒有任何一題是前兩道閘門抓到的**。

### 三道閘門各抓什麼

| 閘門 | 比什麼 | 抓得到 | 抓不到 |
| --- | --- | --- | --- |
| `question_similarity_audit.py` | 字面 3-gram（Jaccard 與重疊係數取大） | 用字接近的重複，跨子分類也有效 | 換代號、換情境 |
| `tool/question_bank_duplicate_audit.dart` | 同 topic + 同 subtopic + 結構標籤 | 只換數字 | 取了不同子分類名的 |
| `question_template_scan.py` | **正規化後**的題幹＋詳解 | 換代號、換情境、換求量位置 | 措辭差異極大的同構題 |

三個一起跑，缺一不可。

### 模板掃描怎麼運作

把人名、英文字母、數字、常見單位都換成佔位符之後再比相似度，這樣
「甲乙丙丁」「PQRS」「MNPQR」會被視為同一件事。實例：

```
logic_grade3_024  P 在 Q 左邊，Q 在 R 左邊，R 在 S 左邊。誰排第三個？
logic_grade5_017  Q 在最左邊，R 在 S 左邊，S 在 T 左邊，U 在最右邊。誰排第三個？
```

字面相似度低於 0.42（代號不同、句長不同），正規化後是同一個骨架。

**關鍵設計：同時要求「詳解也像」。** 只看題幹會誤殺——「求最小的正整數 n 使得…」
底下可以是完全不同的數學，正規化後題幹幾乎一樣，但那是合法的。所以判準是：

- 正規化題幹相似度 ≥ 0.55 **且** 正規化詳解相似度 ≥ 0.60 → 只換皮，要處理
- 題幹像但解法不同 → 合法，放行

用法：

```
python3 scripts/question_template_scan.py                  # 全庫，預設門檻
python3 scripts/question_template_scan.py --min-size 3     # 只看 3 題以上的家族
python3 scripts/question_template_scan.py --prompt 0.50 --solution 0.50   # 放寬重掃
```

### 這一輪抓到的東西

| 家族 | 題數 | 修復前家族內詳解相似度 |
| --- | --- | --- |
| `ordering` 排序鏈（只換字母與問第幾個） | 12 | 0.67 |
| `number_line` 跳格（起點 ±a ±b） | 5 | 0.55 |
| 正方形角落重複計數 | 3 | **0.94** |
| `page_numbering` 頁碼數字個數 | 3 | 0.82 |
| 拼小正方形求周長 | 5 | 0.72 |

還有 30 組兩題配對，最誇張的：`arithmetic_grade6_019`/`_023` 同 pack、
題幹與詳解都是 1.00；`arithmetic_grade6_007`/`_018` 同 pack 連數字都一樣
（6 分鐘/8 分鐘/9:00 同時發車），只差問「幾點幾分」還是「幾分鐘」。

### 工具仍然抓不到的一類：措辭差異極大的同構題

**這一點必須寫下來，因為我在同一輪自己踩了。** 我把
`arithmetic_grade2_022` 換成「三角形外框，三個頂點各 1 顆，每邊數過去恰好
5 顆棋子，共幾顆」（答 12），但 `geometry_grade2_035` 早就有「正三角形每邊排
5 顆棋子，角共用，整圈共幾顆」（也是 12）——數學完全相同。

兩題正規化後的相似度只有**題幹 0.12 / 詳解 0.25**，三道閘門全部放行，
是後來把門檻放寬到 0.50 重掃才連帶露出來的。

所以：

- **模板掃描是第三道閘門，不是萬靈丹。**
- 寫完新題後，除了跑三道閘門，還要人工問一次：
  **「這題的答案和數學結構，和庫裡哪一題一樣？」** 措辭可以差很多，數學不會騙人。
- 補完一批之後，用 `--prompt 0.50 --solution 0.50` 再掃一次，
  看看有沒有東西剛好卡在門檻下。

### 補題時最常見的碰撞來源：自己稍早寫的題

同一個 session 連續補多個年級時，新題本身就是新的碰撞源。這一輪替換題
淘汰了 19 個候選，將近一半是撞到同一天稍早寫的題，例如火車過橋撞
`arithmetic_grade5_073`、三盒糖撞 `logic_grade2_053`、鐘面「轉幾度」撞
`geometry_grade1_062` 的鐘面「走幾大格」。

**每寫完一批就要重跑閘門，不能等到最後才跑。**
