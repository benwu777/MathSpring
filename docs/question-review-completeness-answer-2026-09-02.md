# 題庫複審準則：題幹敘述完整性 + 答案正確性（2026-09-02）

這一輪複審只做兩件事，其他規則一律不管、不順手改。
每個負責 pack 的審題者（人或 agent）都用這一份，標準不得自行加碼或放寬。

## 適用範圍

- 對象：`assets/questions/<topic>/<grade>_foundation.<topic>.v1.json` 共 50 個 pack、2429 題
- 一個審題者負責一個 pack，直接改該 pack 的 JSON，不動別的檔案
- **不在這一輪處理**：去重、難度是否貼齊年級、分類是否正確、圖形品質、來源欄位、四語系翻譯風格

---

## 檢查 A：題幹敘述完整性（只看 `prompt`）

只讀 `prompt` 四語系。判準是：**一個該年級的學生只讀題幹，能不能明確知道要求什麼、條件有哪些？**

### 判為不合格的情況

1. **缺必要條件** —— 解題必需的前提沒寫出來。
   常見漏字：「相異」「不重複」「正整數」「每邊」「至少」「恰好」「連續」「不計順序」。
2. **有歧義** —— 兩種合理讀法會得到不同答案。
   例如：含不含端點、可否重複取、排列還是組合、是否有序、邊界值算不算。
3. **指涉不清** —— 「他」「這個數」「其中一個」「另一邊」找不到明確對象。
4. **缺單位或未指明所求** —— 問「多少」卻沒說單位；或題幹單位與 `answer` 單位不一致
   （例如題目給公升、答案是毫升，題幹卻沒說要換算成哪個單位）。
5. **需要圖卻沒有圖** —— `figure.kind` 是 `none`，而文字沒把幾何關係講完整，
   學生無法從文字還原出唯一的圖形。
   → 這一輪**不補圖**，改成把文字條件寫足；若文字補不出唯一圖形，記進報告標為 `需補圖`，不要硬改。
6. **簡略到要猜出題者意圖** —— 條件要靠常識腦補才成立。
7. **題目本身無解或多解** —— 條件不足導致答案不唯一，或條件互相矛盾。歸在這裡處理。

### 判為合格、不得修改的情況

- **文字精簡但條件齊全** —— 短不等於不完整。這種題一律不動。
- 只是覺得「可以寫得更漂亮」「換個說法更順」—— 不動。

> **這條是硬規則：不要為改而改。**
> 改題幹會改變去重閘門的字面相似度分數，可能讓原本安全的題撞上既有題。
> 每一次修改都必須能說出「原本缺了什麼條件、缺了會怎樣誤解」。

### 修法

- 補上缺的條件，**盡量只加字、不重寫句子**，保留原本的措辭與情境
- 四語系（`zh-Hant` / `zh-Hans` / `en` / `ja`）必須同步補，語意一致
- 不得改變題目的數學內容（數字、情境、所求量都不變），只把原本就成立的隱含條件寫出來
- 若補完發現答案其實會變 → 那是檢查 B 的情況，一併處理並在報告註明

## 檢查 B：答案正確性

### 流程（順序不可顛倒）

1. **先不要看 `solutionSteps`。** 自己把題目重算或窮舉一次，得到自己的答案。
   - 能窮舉的就窮舉，不要憑感覺；必要時寫一小段 Python 驗算
   - `multiple_choice` 要確認「恰好一個選項正確」，不是只確認標的那個能通
2. 拿自己的結果比對 `correctAnswer.value` 與 `answer` 四語系文字。
3. **一致 → 通過，不再讀 `solutionSteps`。**
   這是刻意的：詳解逐題細讀會讓複審拖太久，答案對就放行。
4. **不一致 → 進入「整題調整」**（見下）。

### 整題調整的範圍

答案錯時，以下全部要同步改到彼此一致：

- `correctAnswer.value`
- `answer` 四語系文字
- `solutionSteps` 四語系（此時才需要讀，並確認推導真的導向新答案；四語系陣列長度必須一致）
- `multiple_choice` 且正確答案不在選項內 → 連 `options` 一起改（3–5 個、鍵連續、四語系齊全、選項互不重複）

判斷「哪一邊是對的」的原則：

- 題幹是唯一的事實來源。以題幹算出的答案為準，去修 `correctAnswer` / `answer` / `solutionSteps`
- 只有在題幹本身有缺陷時（檢查 A 第 7 項）才動題幹，且要在報告中明講
- 若整題已經救不回來（條件矛盾、該年級不可能有唯一解），**不要自己換一題**，
  標記為 `需換題` 寫進報告，交回統籌處理——換題必須重跑三道去重閘門

---

## 不得順手做的事

- 不重寫沒有缺陷的題幹
- 不調整難度、不改分類、不改 `subtopic`、不改 `source`
- 不新增或刪除題目（`manifest.questionCount` 必須維持不變）
- 不改 `id`、`levelStage`、`difficulty`、`challengeTier`、`answerMode`、`figure`
- 不動別的 pack 的檔案

## 每個 pack 的回報格式

改完後回報下列內容（沒有問題的題不要列）：

```
pack: <檔名>  題數: <n>  已檢查: <n>
答案錯誤（已修）:
  <id> | 原 <值> → 新 <值> | 原因一句話
題幹不完整（已補）:
  <id> | 缺什麼條件 | 補了什麼（引原文與新文）
需補圖 / 需換題（未動，待裁示）:
  <id> | 問題描述
統計: 答案錯 N 題、題幹補寫 M 題、無異動 K 題
```

## 判準收斂（校準批 logic/grade10 跑完後補，全部 pack 一律照這裡）

校準批 40 題只補 1 題題幹、0 題答案錯，並回報 7 個容易搖擺的點。逐項裁定如下，**不得再自行詮釋**：

1. **題幹字面有 trivial 解時，補條件、保原答案** —— 若出題意圖明確、且補一個限定詞就能排除 trivial 解
   （例如「最小的正整數 n 除以 2、3、4 都餘 1」字面上 n = 1 成立，但意圖是 13），
   一律**補條件保留原 `correctAnswer`**，不要反過來把答案改成 trivial 值。
   只有在補不出合理限定詞、或補了會讓題目變得不自然時，才視為答案錯誤處理。
2. **補條件後，允許只修詳解中因此失效的那一句** —— 不得順帶重寫整段詳解，
   四語系陣列長度必須維持不變，且四語系要一起改。
3. **歧義只有在「兩種讀法會導致不同答案」時才算不合格** —— 「1 到 9 之間」「一天以內」這類
   含不含端點的寫法，若兩種讀法答案相同，**一律不動**。不要把所有「之間」「以內」都補成「含端點」，
   那會把字面相似度整批推高。
4. **不影響答案的隱含前提不算缺陷** —— 例如沒寫「兩個沙漏一開始都是滿的」「吐司一開始都是生的」，
   若答案不受影響，歸為「文字精簡但條件齊全」，不動。
5. **翻譯較拗口不處理，無法還原唯一題意才算 A-3** —— 例如「甲乙丙丁」譯成 the first person，
   讀者仍能還原題意 → 不動。只有該語系讀者無法確定題意時才補。
6. **題幹裡的 `**` 粗體標記不在本輪範圍** —— 全庫有 79 題題幹含 `**`，
   app 沒有 markdown renderer，會原樣顯示星號。這是另一輪的批次處理，**審題者一律不要動它**。
7. **`answer` 文字格式（字母／內容／數字）不統一，本輪不動** —— 同一 pack 內出現三種寫法是既有狀況，
   統一與否留待後續決定，不要順手改。

補充：校準批的命中率是 1/40。**這是正常的，不要因為「都沒找到問題」就放寬標準去湊出修改。**
一個 pack 全部無異動是可接受的結果。
